JSON import formats

Use Settings & backup → Import backup or catalog. Vaayana detects one of the two formats below. It reads the file locally and shows a preview before saving anything.

  • Download a small invented catalog example · Catalog JSON Schema
  • Download an app-generated, generic backup example · Backup JSON Schema

A catalog is not a backup. A catalog supplies titles, authors, and source information. A Vaayana backup can carry your private diary, reading history, settings, and saved library records. Neither choosing a catalog nor previewing it starts an online lookup or model download.

1. Book catalog

The root must be an object with a books array, not a bare array. These example books are invented:

{
  "total_unique_titles": 2,
  "notes": "An invented two-book catalog example, not a full library backup.",
  "books": [
    {
      "title": "A Field Guide to Clouds",
      "author": "Alex Example",
      "source_images": [1]
    },
    {
      "title": "The Quiet Orchard",
      "author": null,
      "source_images": [2, 3],
      "notes": "The author was not identified."
    }
  ]
}

Allowed root fields

FieldRequired?Meaning
booksYesArray of book objects, including an empty array. At most 10,000 entries.
total_unique_titlesNoDeclared count, a whole number from 0 to 1,000,000,000. The actual array count is authoritative. A mismatch warns; it never truncates, pads, or deduplicates the list.
notesNoCatalog-level source notes, at most 20,000 characters. Kept on the import receipt, not copied into personal reading notes.

Allowed fields in each book

FieldRequired?Meaning
titleYesNon-blank string, at most 1,000 characters. Keep the complete title, including volume, edition, or translation details and Unicode text.
authorYesString of at most 500 characters, or null if unknown. A blank string also means unknown. No author is guessed or split into multiple authors.
source_imagesNoUp to 10,000 whole-number image references, each from 0 to 1,000,000,000. These are references only, not image data or URLs. No image is uploaded or downloaded.
notesNoSource-entry notes, at most 20,000 characters, including any uncertainty. Kept with unverified source provenance, separate from your diary.

Only these fields are accepted. Use valid JSON: double quotes, no comments, no trailing commas. Unknown fields are rejected rather than silently discarded. Every file is limited to 20 MiB of UTF-8 bytes; the resulting library must also fit the backup record limits below.

Preview, defaults, and duplicate safety

  1. Choose the file. Check the detected format, actual entries, declared total, unknown authors, source notes, and warnings. Previewing has not saved books.
  2. Choose a starting shelf: To read (default) or Wishlist. Choose owned formats: Unknown / no copy specified (default), physical, digital, or both. Choices apply only to new books.
  3. If an entry resembles a saved title/author, Skip entry is the default. You may explicitly Add as a separate book, never replace the existing book. A previously deleted entry needs an explicit restore choice when offered.
  4. Optionally download a pre-import backup. This refreshes the preview and resets your review while keeping the catalog choices.
  5. Review again, check the confirmation box, then select Import reviewed catalog. Or select Cancel import to discard the preview.

All imported source text remains unverified. Original title, original author (including null), image references, and entry notes are preserved and visible under the book journal's Sources tab. Catalog-level source notes remain in the import receipt. A full backup preserves both.

A catalog creates no reading cycles, finished dates, reading-status events, or sessions. It infers no ISBN, page count, language, rating, tag, Layer, or provider fact. Existing corrections, notes, holdings, and reading history remain unchanged. Edition-, translation-, revision-, and volume-specific entries remain distinct. Repeated identical rows are kept separately with a warning.

Repeating the same imported file does not duplicate its books or resurrect deleted entries. Formatting or key-order changes do not create a new source identity. Overlapping catalogs may add source provenance without replacing your edits. Changing source-row content can represent a new entry, so review any possible-duplicate choices rather than relying on title-based merging.

2. Vaayana backup

Make this file with Export backup. Import it unedited. Do not rename catalog fields or invent internal IDs to imitate a backup.

A backup contains "format": "vaayana", "formatVersion": 1, "schemaVersion": 1 or 2 (current exports use 2), exportId, sourceLibraryId, exportedAt, and an entities object containing the supported record stores. The downloadable backup example was produced by the app exporter, using only generic invented data.

Backups validate structure, versions, IDs, relationships, supported URLs, and limits before a merge. They retain revision and deletion information. Local edits and deletions win by default; changing or restoring conflicting records requires an explicit decision. A malformed backup is not reinterpreted as a catalog.

Update the receiving app first. Before importing a newly exported backup on another device, open Vaayana online and reload the latest version. Older app copies can reject the new optional catalog-source and starting-shelf fields, even though the backup format/schema labels are unchanged. The current app reads older backups. Keep your original file if you cannot update yet.

Limits: 20 MiB total, 50,000 user records plus 100,000 deletion/import-provenance records, with field, array, and nesting caps. The schemas describe JSON structure. The importer additionally checks relationships, valid identifiers, aggregate limits, and other semantic rules that JSON Schema alone cannot establish.

Backups are not encrypted. They can contain private notes, history, settings, and source material. Save them somewhere safe. Do not publish your real backup or catalog as an example.

If an import is rejected

  • Invalid JSON: check double quotes, commas, and closing brackets. The importer does not quote private book text in parsing errors.
  • Unsupported format: use an app-exported backup or an object containing a books array. CSV, a bare array, and arbitrary third-party backups are not guessed.
  • Unsupported fields: compare the field names with the tables above. For an unknown author, include "author": null rather than omitting the field.
  • Declared count differs: this is a warning, not a reason to trim the list. The preview uses every actual entry.
  • Library changed after preview: choose the file again and review the new preview, including any new conflicts.

Malformed files, cancelled previews, stale previews, and failed writes leave the saved library unchanged. Accepted records and their source information are saved together, not as a partially imported list.
